# 产品案例：从“模型能识别”到“业务敢使用”

## 背景

订单来自 PDF、Word、Excel、扫描件和图片。AI 可以减少重复录入，但字段错误可能继续影响 ERP、MES、排产和交付。

## 产品判断

核心目标不是让模型输出 JSON，而是在降低人工录入成本的同时，把高风险错误阻断在进入生产系统之前。

## 方案

1. 用固定数据集和人工标准答案建立稳定基线。
2. 按字段业务后果进行风险分级。
3. 同时衡量准确性、完整性、稳定性和整单质量。
4. 将错误定位到具体订单和字段，形成可复核证据。
5. 用明确门槛生成发布、灰度或阻断建议。
6. 将高风险错误和不确定结果送入人工复核。

## 个人能力体现

- 把模糊的“AI 准不准”转化为指标体系和决策门槛。
- 从用户、业务流程和错误成本确定优先级。
- 平衡自动化效率与企业风险，不追求不受控的全自动。
- 把一次问题沉淀为固定数据集、回归机制和迭代闭环。

## 事实边界

本 Demo 使用模拟数据，展示的是基于真实项目经验提炼的方法。原生产系统由开发团队实现，本仓库不包含原系统代码或真实客户数据。
